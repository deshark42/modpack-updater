# Agent Note: 发布内容不得接管更新器状态

Status: implemented

## 问题

发布清单控制订阅者要新增、替换和移走的文件；`.modpack-updater/` 则保存连接配置、各 tag 的指针、历史清单、备份、临时文件与日志。如果发布内容能命名这个目录，远端就能改写下一轮更新的信任来源，或覆盖更新据以决策和恢复的数据。仅校验路径没有离开工作区不足以隔离这两个权限范围。

## 决策

`SafePath.require` 在规范化后的首个路径段上保留整个 `.modpack-updater` 命名空间，包括该目录本身。大小写以及首段尾点、尾空格的 Windows 别名在所有发布平台上一并拒绝，避免 Linux 发布出 Windows 上能覆盖状态的清单。其他位置同名的嵌套目录、带额外后缀的普通名称仍可追踪。

`Manifest` 的构造与解析均执行该校验；订阅者读取远端目标清单和本地旧清单时都适用，不能通过旧清单的删除集合绕过。发布者在合并 base、overlay 与 remove 规则后、访问对象存储前校验最终路径集合，因此被 remove 排除的输入不影响发布，有效输入中的保留路径则使整次发布失败。工具通过 `Layout` 管理内部状态，不通过发布清单更新自己的配置。

[发布格式](../architecture/2026-10-14-release-manifest-and-config.md)、[发布者工作区](../architecture/2026-10-13-publisher-workspace.md)和[订阅者流程](../architecture/2026-10-14-subscriber-workspace.md)仍分别持有格式、工作区与差异更新语义，本记录只补充发布内容与工具状态之间的权限边界，没有完全取代这些记录。[更新器本体与信任根保护](2026-10-26-protect-running-updater-and-trust-root.md)另外保护实际加载的代码位置并补全缺失密钥的位置校验，不取代本记录的状态命名空间规则。

## 曾考虑的替代方案

**只禁止 config.json。** 不采用：指针、历史清单与备份同样影响后续更新和恢复；逐个列文件还会让未来新增的内部状态默认暴露给发布者。

**只在发布端过滤或校验。** 不采用：另一个桶写入者可以绕开发布工具，本地也可能保留旧工具接受的清单。两端都应拒绝非法内容，而不是静默丢弃条目后产生与发布者不同的更新结果。

## 后果

- 以前包含保留路径的 release 或本地清单现在会明确失败；必须由操作者修复，工具不会自动删除或迁移它们。目标 release 已应用的无操作运行不读取本地旧清单，这类清单留到下一次会变更的运行时失败（[release 已应用时不再预检旧清单](../simplification/2026-10-27-skip-preflight-when-release-is-already-applied.md)）。
- `SafePathTest` 持有路径及跨平台别名矩阵；`ManifestTest` 覆盖直接构造入口；命令测试覆盖发布前拒绝、远端覆盖配置以及旧清单触发删除三条实际接线，并检查桶、配置、文件和指针没有对应副作用。
- 这是命名空间保护，不验证发布者身份，也不阻止发布者更新正常模组或游戏配置；真实文件系统的别名由[链接重定向保护](2026-10-25-reject-workspace-link-redirections.md)约束。
