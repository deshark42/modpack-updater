# Agent Note: 拒绝工作区内部的文件系统重定向

Status: implemented

## 问题

清单路径没有 `../` 并不代表最终访问仍在工作区：实例里的目录符号链接或 Windows junction 可以把普通相对路径带到外部，也能让 `mods/` 之类的名称映射到[保留的内部状态](2026-10-25-reserve-updater-state-paths.md)。配置、备份、临时文件与日志同样可能经链接改写外部数据。逐个执行到哪个路径才检查哪个路径，还可能在发现后面的危险项前已经替换前面的安全文件。

## 决策

`fs.PathGuard` 校验指定根以下每一个已存在的路径段：逐段读取不跟随链接的属性，拒绝符号链接和特殊节点，再将最深已存在目录的真实路径与根的真实路径加相对后缀比较，拒绝原生别名或目录联接。遇到缺失节点或普通文件阻挡后续路径时，仍校验此前最深现存目录的真实路径；缺失的路径段可以稍后创建，普通文件挡住的后续段也可以在应用阶段重建。普通文件叶子只比较它已存在的父目录，叶子自身不再解析真实路径（[目录级真实路径解析](../simplification/2026-10-27-resolve-one-directory-per-preflight-path.md)）。用户主动指定的工作区根本身可以是链接，其实际位置就是信任边界；根以下指向内部的链接也拒绝，避免别名绕过保留目录规则。

真实路径解析集中到最深现存目录，避免 Windows 的 `toRealPath()` 为每个前缀反复查询同一组祖先；一次批量预检因此只为每个唯一目录解析一次。`PathGuard.at(root)` 为一次发布的用户输入遍历与后续源文件访问，以及单次临时树清理捕获已存在的受信根真实路径；各次 `require(path)` 仍重新读取全部已存在子路径段的属性并解析该路径最深现存目录，不缓存子路径的安全结论。捕获的根不可变，可以供并行分块读取共用。静态 `require(root, path)` 继续支持尚未创建的工作区。专属解包树使用[暂存树条目校验](2026-10-25-skip-redundant-staging-path-checks.md)，不在创建和写入每个条目时重复走 `PathGuard`。

`PathGuard.inspectAll(paths)` 仅供单次、同步且不修改本地树的整组预检使用：同一次调用内复用共享路径段的不跟随链接属性（含缺失结果）和最深现存目录已经成功的真实路径比较，返回已完整存在的请求路径属性；普通文件阻挡的后续路径不返回该文件的属性。不带预检参数的 `inspectAll` 与普通 `require` 每次重新检查子路径；一条路径能否复用只由调用方显式传入的 `PathGuard.Preflight` 决定。会改动载荷的更新在两次清单预检之间没有本地写，因此在它们之间共用一个预检（[单一只读预检轮次](../simplification/2026-10-27-share-one-readonly-preflight-per-update.md)），但不把预检复用于下载、应用、清理或后续 tag——那些阶段会写入工作区；目标 release 已应用的无操作运行不读取本地清单（[release 已应用时不再预检旧清单](../simplification/2026-10-27-skip-preflight-when-release-is-already-applied.md)）。整份清单并行分片时，各分片各有独立的 `inspectAll` 快照，仅共享捕获的不可变根；所有 reader 在预检返回前结束，生命周期由[更新器保护](2026-10-26-protect-running-updater-and-trust-root.md)持有。每个不同的最深现存目录仍经真实路径比较，因此缺失后缀、Windows 原生目录别名和 junction 的边界不变；普通文件叶子的拼写别名不在比较范围内（[目录级真实路径解析](../simplification/2026-10-27-resolve-one-directory-per-preflight-path.md)）。

`SafePath.resolve` 保护发布内容的访问；`Layout` 的所有路径出口保护内部状态和发布输入。更新在读取目标清单后预检目标清单落盘位置；下载或移动文件前的逐条目的地预检只针对备份目的地，因为新增、替换、删除的全部源路径已由上述两趟清单预检覆盖（[单一只读预检轮次](../simplification/2026-10-27-share-one-readonly-preflight-per-update.md)）。保留备份的遍历和临时目录的清理在读取内容或删除之前也逐项检查；清理先收集并校验整棵树，发现链接时不开始删除。发布树遍历不跟随符号链接，并在遍历目录和普通文件时检查 junction 等别名；用户提供的发布输入目录逐项检查，而本轮新建且由解包器独占写入的暂存树只在创建暂存根时校验一次（[解包暂存树](2026-10-25-skip-redundant-staging-path-checks.md)）。

日志系统还检查最终日志文件名和清理候选项，防止目录安全、日志文件本身却是链接时追加到外部文件。安全校验错误不会被当成可忽略的日志写入失败或本地复用失败。

[订阅者工作区](../architecture/2026-10-14-subscriber-workspace.md)、[发布者工作区](../architecture/2026-10-13-publisher-workspace.md)与[状态命名空间保护](2026-10-25-reserve-updater-state-paths.md)继续持有各自独立的布局、更新及保留名称语义，本记录补充真实文件系统的解析边界，不取代这些决策。

## 曾考虑的替代方案

**只比较拼接、规范化后的字符串前缀。** 不采用：这正是符号链接和 junction 能绕过的检查，不能代表真实文件系统的访问位置。

**允许目标仍在工作区内的链接。** 不采用：内部链接可以别名访问配置和状态，也会让同一目录在备份、复用和清理阶段具有多种身份；显式拒绝更容易保持命名空间边界。

**只检查目标文件写入。** 不采用：旧文件读取、备份移动、状态落盘、日志追加和临时树清理都能通过链接越界，且逐项应用时发现危险过晚会留下部分更新。

**跨调用缓存已检查的子路径。** 不采用：先前不存在或安全的目录随后可能被替换为链接；普通逐次访问仅复用受信根；批量预检的共享子路径快照只能在调用方显式限定的只读窗口内传递，每次新预检与普通 `require` 重新检查（[单一只读预检轮次](../simplification/2026-10-27-share-one-readonly-preflight-per-update.md)在同一轮只读预检内部接受了复用）。

## 后果

- 原来通过内部链接共享模组、配置或状态的实例现在明确失败，操作者需要移除这些链接或把所需文件放在真实目录中；工作区根仍可通过用户指定的链接选择。
- `PathGuardTest` 覆盖新路径、普通文件转目录、外部目录链接、内部别名、根链接和悬空文件链接，也覆盖普通调用和批量预检之间目录替换后拒绝链接，以及两种入口对 Windows 原生目录别名后的已存在/缺失后缀的拒绝；Windows 用例另外钉住普通文件叶子的结尾点重拼写被接受，以及 8.3 目录别名不能隐藏 junction。批量用例另外验证共享父目录、缺失后缀与普通文件阻挡时返回的末端属性。Windows 的目录用例真实创建 junction，无需符号链接特权；文件符号链接用例仅在平台不支持或缺少权限时跳过。
- `UpdateTest` 覆盖新增、替换、删除前的整体预检，以及状态根、备份、版本目录、临时树、配置和日志的链接；断言外部文件及先于危险项的正常文件不变、指针不推进、危险状态不触发块下载。相关命令与文件系统测试继续覆盖普通更新和恢复流程。
- 额外的真实路径和属性检查增加本地元数据访问；每条路径最多解析一个现存目录。它防御检查时已存在的链接，不能锁住另一个拥有同一目录写权限的本地进程；跨平台实现不承诺对并发替换路径的攻击提供原子隔离。批量快照使共享路径的检查时刻提前到本轮首次访问，因此必须限定为只读预检，不能当作随后写入的授权。普通硬链接不视作路径重定向。
