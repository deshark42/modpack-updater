# Agent Note: release 不得接管更新器及本地信任根

Status: implemented

## 问题

发布签名证明某份 release 获得发布者授权，却不应授予发布者改写订阅者验签程序及信任来源的权限。状态目录已有保留命名空间，但正在运行的更新器可能位于实例任意位置；清单既能替换文件，也能把整个旧目录移入备份。只禁止某个固定 JAR 名称或只检查新下载项，仍会留下重命名、父目录删除和未变条目等绕过方式。

## 决策

[UpdaterProtection](../../../../src/main/java/io/github/deshark42/modpackupdater/security/UpdaterProtection.java) 根据加载的 `Main` 的 protection domain / code source 定位实际代码，不接受发布内容或配置指定受保护位置。以 JAR 运行时保护实际文件；以 classpath 运行时保护实际 classes 目录。无法定位或解析本地代码位置时拒绝更新，不静默跳过。

清单路径与代码位置相同、是其祖先或后代时均拒绝，比较使用路径段而非字符串前缀。检查以工作区根的实际位置为基准，保留用户主动选择根目录链接的能力；根以下继续使用现有链接与原生别名检查。已有文件与更新器具有相同文件身份的硬链接也保守拒绝：这是所有权限制，不是声称原子替换一个硬链接必然改写另一个链接的 inode 内容。

[Update](../../../../src/main/java/io/github/deshark42/modpackupdater/command/Update.java) 在相同版本的提前返回之前检查全部本地旧清单，在验签及身份匹配后检查全部目标清单，而不是只检查 diff。失败发生在请求块表与内容块、暂存、备份和应用之前；不能借删除旧条目、相同哈希或本地已有相同内容绕过。

本地信任配置仍由[状态命名空间](2026-10-25-reserve-updater-state-paths.md)、[发布签名](../feature/2026-10-25-ed25519-release-signatures.md)和[链接保护](2026-10-25-reject-workspace-link-redirections.md)共同持有。它们分别记录保留状态、认证协议和文件系统访问规则，本记录只扩展更新器本体保护并补全密钥位置检查，没有完整取代任何一份记录。

`Config` 对尚不存在的密钥也解析其最近可解析祖先，再接回缺失后缀，避免配置在工作区外的路径经已存在的链接父目录实际落入可发布内容。不可解析的现有链接不当作普通缺失目录放行。`update` 检查公钥和私钥的配置位置，但只加载公钥；订阅者无需持有私钥。工作区内的密钥仍必须在状态目录中，工作区外的正常密钥仍可使用。

## 曾考虑的替代方案

**只禁止固定更新器文件名。** 不采用：用户可以重命名或移动 JAR，也可能从 classpath 运行；保护实际加载的代码位置才与执行权限一致。

**只检查下载集合，或签名有效就允许自更新。** 不采用：旧清单删除、父目录替换与同哈希跳过都可能绕过下载检查；有效签名不等于订阅者同意把程序和本地信任根的控制权交给 release。

**额外禁止所有脚本或可执行扩展名。** 不采用：启动脚本可能是合法整合包内容，模组本身也执行代码；扩展名黑名单不能提供沙箱，也不能代替更新器与信任配置的权限边界。

## 后果

- 无绕过选项；冲突使当前 tag 失败，不静默过滤清单。已有冲突的本地记录需由操作者修复；更新器升级及公钥更换通过独立可信渠道完成。
- 工具仍可维护自己的状态、运行日志与缺省配置字段；批量更新中此前成功的 tag 不回滚。
- 单元测试覆盖真实代码位置、改名及空格、双向路径前缀、classes 目录、外部代码、硬链接、工作区根链接及缺失密钥父目录。命令测试覆盖有效签名的冲突、内容已匹配、旧清单删除/未变/相同版本、信任配置与密钥命名空间，并检查受保护文件、普通文件、状态和请求序列。
- 不是本地并发路径替换的锁，也不是脚本或模组沙箱；受信发布者仍能更新合法的模组与启动脚本。
