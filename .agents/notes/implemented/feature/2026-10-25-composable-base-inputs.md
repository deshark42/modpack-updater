# Agent Note: 可组合的目录与压缩包 base 输入

Status: implemented

## 问题

官方整合包通常以 ZIP 或 7z 下载，要求发布者逐包手工解压会留下重复准备步骤。原来在 base/、base.zip、base.7z 中三选一，能省去单包解压，却不能同时发布直接维护的文件与多个独立下载的包，也无法用包所在目录表达目标位置。需要组合这些来源，而不让同名内容依赖扫描顺序，不改变 overlay、删除规则、订阅者或对象存储格式。

## 决策

一个 tag 的 base 来自两个可并存的目录：`<tag>/base/` 直接提供原样文件；`<tag>/base_pack/` 递归收集任意名称的 ZIP / 7z，扩展名不区分大小写。每个包的输出路径是它在 base_pack/ 下的相对父目录加包内路径，不增加包名这一层，不剥掉包内顶层目录，也不继续展开包内的 jar、zip 等文件。base_pack/ 是包容器，不是普通文件来源：不支持格式的文件直接报错，空容器子目录自身不产生输出。两个输入允许各自缺失、允许为空，但至少一个目录必须存在；候选根的错误类型或链接不被当成缺失忽略。init 创建两个目录。没有新增 CLI 参数或配置字段。

所有输入在任何存储访问之前完成解包与冲突校验：重复文件路径即失败，即使内容相同；文件与目录的同名或前缀冲突同样失败，包括 base/ 的实际空目录、包内显式空目录和解包条目所需的映射父目录。同名目录可以合并；不同包之间遵循相同规则。校验先于 remove 与 overlay，因此删除或覆盖规则不能掩盖来源歧义。碰撞登记另使用发布机 FileSystem 的目标 Path 身份及逐级父路径，清单仍保留原始逻辑拼写，避免 Windows 的本机大小写别名跨独立解包目录漏过检查。旧 tag 根的 base.zip / base.7z（含大小写变体）不再作为输入，发现时提示移入 base_pack/，防止 init 的空 base/ 导致旧内容被静默遗漏。

Apache Commons Compress 读取 ZIP / 7z，显式携带 XZ 运行时依赖以支持常见 7z 的 LZMA / LZMA2，不调用系统 7z 或 unzip。每个包在 `.modpack-updater/tmp/` 下的唯一专属目录中按条目流式展开；BaseSource 保留逻辑目标路径到实际源文件与大小的映射，不复制 base/ 内容。所有解包目录保留到整个 publish 返回，因为分块只记录源文件位置，上传时还会随机重读对应区间。正常成功、异常或合并冲突均清理已打开的全部包；不改写原始输入，也不清理更新器的 tmp/blob、tmp/file 或其他发布任务的内容。

解包路径校验与发布路径校验分开：前者拒绝绝对路径、盘符、反斜杠、空路径段、`.` / `..` 段、重复条目、文件与目录冲突，以及链接、特殊文件和不支持的条目；ZIP 条目名必须严格按 UTF-8 解码，未带 UTF-8 标志、没有 Info-ZIP Unicode Path 字段、名字字节也不是合法 UTF-8 的旧式编码名称会被拒绝，因为库的替换式解码会把它静默变成乱码路径；带 Unicode Path 字段的条目改用该字段，字段载荷同样必须严格按 UTF-8 解码。真实文件系统访问仍经过 [PathGuard 边界](../bug-fix/2026-10-25-reject-workspace-link-redirections.md)，但本轮新建的专属暂存树只在创建暂存根时校验一次，包内条目不再逐条重查（[解包暂存树校验](../bug-fix/2026-10-25-skip-redundant-staging-path-checks.md)）。ZIP 内容显式核对长度与 CRC，损坏或不可读压缩包使整次发布在上传前失败。

解包器不因为条目位于保留名称空间就提前过滤；[状态路径保护](../bug-fix/2026-10-25-reserve-updater-state-paths.md)仍由 remove 与 overlay 合并之后的有效路径校验持有，因而被 remove 排除的状态路径与目录 base 保持相同语义。remove 作用于合并后的逻辑 base 路径，overlay 仍对该逻辑空间新增或覆盖，不修改来源之间的冲突规则。

本记录合并并取代原“压缩包 base 输入”记录，保存其安全解包、临时物化、被否决替代方案及覆盖限制；三选一来源规则被可组合输入取代，其防止陈旧输入误发布的目的由逐路径冲突与旧位置迁移错误承担。[发布者工作区](../architecture/2026-10-13-publisher-workspace.md)继续持有配置、命令与发布生命周期，[overlay 与删除清单](../architecture/2026-10-14-publisher-overlay.md)继续持有合并与删除语义，两个安全记录继续持有各自边界；这些部分重叠记录保留活跃，没有需要归档的完整历史决策。

## 曾考虑的替代方案

**保留单一 base 目录或单个固定名压缩包三选一。** 能避免选错旧包，却阻止多包与普通文件共存；将包名任意化、用父目录挂载并在实际输出冲突时失败，既满足组合需要，也不设隐式优先级。

**增加 publish --base <path> 或每 tag 的配置。** 不采用：两个固定角色的输入目录已经允许保留下载包名与表达目标位置，无需扩大 CLI 或持久化配置面。

**直接从压缩流分块和上传。** 不采用：去重规划与实际上传分开，Placement 在上传时随机重读源文件；7z 的 solid 数据又不适合按块重复随机解压。先物化能复用分块、去重和并发上传，不把压缩源带进存储协议。

**把压缩包解压进 base/ 并持久保留，或把全部 base 文件复制成临时合并树。** 不采用：前者在失败时留下新旧混合树并可能覆盖自有输入；后者为未压缩文件重复付出磁盘和 I/O。专属解包目录加逻辑路径映射避免两者。

**自动剥掉唯一顶层目录、按包名新增目录层、或在冲突来源中设优先级。** 不采用：这些选择静默改写清单路径或选错内容，订阅者可能据此删除原路径。包所在父目录明确表达挂载位置，文件冲突必须由发布者解决；内容相同也不能证明两个来源的未来更新仍一致。

**对所有逻辑路径统一转小写。** 不采用：这会把 Linux 上合法的不同文件合并为同一个目标，并扩大为面向其他订阅平台的名称政策。当前只用发布机 FileSystem 的 Path 身份登记碰撞，修复 Windows 本机同目标与祖先别名，不改写清单拼写。

**继续自动读取旧 tag 根的 base.zip / base.7z。** 不采用：同时保留两套发现规则会隐藏仍在使用的旧输入，并增加组合歧义。迁移错误比忽略旧包后发布空目录更安全，移动包到 base_pack/ 根目录即可保留原输出路径。

## 后果

- 发布者可以组合目录文件与多个包，overlay 与 remove.txt 保持独立；云端发布格式、签名与订阅者不变。扫描日志与分块读取使用同一逻辑路径映射。
- 每次发布都完整解压全部包，需要容纳所有解压内容的额外磁盘空间；没有跨次缓存。解包是顺序读取，不把整份内容装入内存；解包开始与完成各记一行 INFO，报告文件数、大小与耗时（[解包暂存树校验](../bug-fix/2026-10-25-skip-redundant-staging-path-checks.md)）。来源校验、解包和冲突检测先于存储访问，因此已存在版本号等存储错误到解包后才报告，重复发布会多付解包成本。
- 不支持加密、多卷或库不能读取的包；没有密码输入或外部命令回退。Commons Compress 不支持 7z 多输入/输出流编码链，例如 7-Zip 对可执行文件使用的 BCJ2 过滤器：7z2301-extra.7z 已有实测，错误保留库原文及包路径，需改用 ZIP 或关闭该过滤器。7z 解码器内存上限为 256 MiB，拒绝更大字典，避免畸形元数据请求近乎无限内存。
- 7z 条目名按 UTF-16 解码，库对不成对代理项替换解码；头部校验自洽的人造包可能得到含 U+FFFD 的名称，该名称仍是合法路径且在发布者与订阅者间一致，不额外拒绝。没有新增全包大小上限；发布者须信任输入并准备资源，路径与条目校验不等于压缩炸弹资源隔离。
- 正常成功与异常退出都会清理 staging；强制终止或清理自身失败仍可能留下临时内容。PathGuard 不承诺抵御其他本地进程并发替换路径。
- 清单保留原始路径拼写，碰撞按发布机 FileSystem 的 Path 身份判定，不新增跨平台大小写折叠或 Unicode 归一化策略。Windows Path 身份会拒绝不同来源的大小写别名；Unix Path 身份仍区分大小写，不额外探测卷级大小写或 Unicode 归一化规则，因此 Unix 上特殊卷的别名仍有未覆盖边界。单包的本机别名还可能在 CREATE_NEW 失败，不能把这种单包物理检查当成跨包兜底。Windows 发布机在解包前拒绝设备名与结尾点/空格，并检查可能的 8.3 目录别名，避免平台丢弃内容或改写名称；普通暂存条目不重复解析物理路径，其他平台不新增 Windows 名称限制（[解包暂存树校验](../bug-fix/2026-10-25-skip-redundant-staging-path-checks.md)）。
- BaseArchiveTest 持有 ZIP / 7z 安全解包、UTF-8 名称与旧式编码拒绝、危险条目、内容校验和清理覆盖；BaseSourceTest 持有目录组合、路径映射、目录/文件碰撞与来源生命周期；BaseSourceTest 与 PublishTest 按原生 Path 身份分别覆盖 Windows 别名拒绝与 Unix 不同大小写路径共存；PublishTest 还持有真实发布清单、remove/overlay 接线及失败零存储副作用；InitTest 与 LayoutTest 锁定两个目录的工作区约定。
