# Agent Note: 交互发布基线预览

Status: implemented

## 问题

发布完整清单足以驱动订阅者更新，但发布者在确认之前看不到实际增删改，尤其容易遗漏输入目录消失或 remove 规则造成的删除。多 channel 下，“上次发布”也不是一个本地全局版本：需要明确比较的是操作者将要推进的 channel。

## 决策

真实终端中缺少 tag 或 id 的 publish 向导，先选择工作区、编号 tag 和 channel，再读取该 channel 指向的 release_id，显示其清单到本次完整载荷的哈希差异，最后以输入新 release_id 作为发布确认。完整 tag/id 参数仍走直接发布入口，不新增历史清单或公钥依赖，不维护本地 release 发布历史。channel 菜单使用当前工作区和 tag 的本地通道名历史，latest 固定第一且默认；可按编号选已有名称或填写新名称。历史只在 CLI 发布或按通道更新成功后尽力记住，不是远端清单、当前选择或发布基线，具体布局见[发布者工作区](../architecture/2026-10-13-publisher-workspace.md)。

预览直连配置的对象存储 endpoint，不经过订阅者的 read_endpoint；使用本地 trusted_public_key 对清单原字节验签后才解析，并核对 tag 与 release_id。只有所选指针不存在才能视为首次发布；损坏指针、缺失目标或签名、验签失败、身份不符和网络错误均失败关闭。无指针选择明确没有比较基线，不回退到 latest。channel 指针本身仍未签名，这不提供新鲜度或防回退保证。

预览和发布共用一次 base、压缩包、remove 与 overlay 合并、分块结果。Prepared 持有完整文件条目、块表、块读取位置和本次解包目录直到关闭，确认后不重新扫描或解包。这样屏幕上的 diff 与发布清单来自同一份载荷，且不需要复制所有普通文件。确认后、发布写入前复核配置、所选指针和所有保留文件的大小与整文件哈希；重复内容、空文件和已存在于桶中的块也不能跳过文件复核。

确认前允许读取配置、S3 基线和载荷，以及在工作区临时展开压缩包，但不补写配置、不打开 transcript、不写 blob 缓存、通道历史或上传对象。取消、I/O 错误、准备失败和发布结束均清理本次拥有的解包目录，不删除共享临时目录中的其他内容，临时父目录可能保留。

### 记录归属与部分取代

本记录部分取代[发布者工作区](../architecture/2026-10-13-publisher-workspace.md)中发布侧不比较历史清单的选择，仅为交互入口提供审阅基线；旧记录的完整清单、配置归属、不可变 id 与脚本兼容依据继续有效，保持活跃。[overlay 与 remove](../architecture/2026-10-14-publisher-overlay.md)和[分块传输](../architecture/2026-10-22-content-defined-chunked-transfer.md)继续持有输入合并和内容去重依据：diff 不产生删除规则，也不决定上传哪些块。[发布签名](2026-10-25-ed25519-release-signatures.md)继续持有原字节认证与信任根规则；这里只增加一次历史清单的使用场景。它们均有独立、仍约束后续工作的理由，无记录被完整取代或符合归档条件。

## 曾考虑的替代方案

**继续只显示参数摘要再确认。** 不采用：参数不能显示压缩包、overlay 和 remove 合成后的结果，操作者仍须在发布后才发现意外删除。这里接受历史比较用于审阅，不把它变成发布内容的来源。

**只比较 base 目录，确认后再执行一次普通发布。** 不采用：忽略压缩包、overlay 或 remove 会显示错误差异；再次合并或解包还会允许发布内容与刚才确认的载荷不同。保留一次准备结果，在读取原文件上传时仍校验块哈希。

**用 CDN 或未验证清单作预览，读取失败则当作空版本。** 不采用：缓存可能显示陈旧基线，损坏或未授权清单会误导最终确认。权威源站读取仍不能证明指针新鲜，但能避免主动引入订阅缓存，并复用现有可信签名规则。

## 后果

- 已有 channel 的交互预览需要能验证该 release 的本地公钥；密钥轮换后不能验证的历史版本会停止向导，而不是降级。完整参数发布仍可在无公钥、无有效旧指针时发布新版本。
- 预览需要联网、读取和分块整个载荷；有压缩包时要在最终输入 id 前付出展开时间和磁盘空间，等待确认期间暂存内容仍占空间。
- 配置、channel 或保留文件变化会要求重新预览。检查不是 compare-and-swap，也不锁住并发发布者或本地编辑；预览后的新增路径不会被重新扫描纳入载荷。确认后上传失败仍可能留下不可变对象，不提供回滚。
- diff 只表示所选 channel 当前清单到准备载荷的变化，不代表所有订阅者的当前版本，也不是网络上传量估算。完整清单与订阅更新语义不变。
- PublishPreviewTest 覆盖权威源站、验签与身份失败关闭、真实合并差异、准备阶段无发布写入、解包生命周期、预览后文件及指针变化和脚本兼容；CLI 测试覆盖显示 diff 后才读取最终 id、取消和终端断开时不发布。
