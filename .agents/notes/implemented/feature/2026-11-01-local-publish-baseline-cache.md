# Agent Note: 发布基线的本地签名副本

Status: implemented

## 问题

同一工作区发布后，交互向导再次比较该版本仍要下载完整清单及签名。release 在一个存储位置和 tag 内不可变，可以复用已上传的字节；但 channel 可由另一台机器推进，不能把“本地最后发布的版本”当作它的当前状态，也不能把订阅者用于恢复实例的本地清单当作已认证的远端副本。

## 决策

publish 在全部远端写入成功后，尽力保存本次签署并上传的原始未压缩清单和原始签名。向导每次仍从源站读取所选 channel 的 release_id，只对这个 id 优先使用本地副本；命中时不再 HEAD 或 GET 该清单和签名。使用当前 trusted_public_key 先验签再解析，并要求 tag、release_id 精确匹配。不可用的本地副本只代表缓存未命中，回源重新读取整对清单和签名、完整验证；回源失败仍停止预览，不当作空版本。

缓存路径为 `.modpack-updater/<tag>/published-releases/<location>/<release_id>.json` 及相邻 `.json.sig`，location 是 endpoint、bucket、规范化 prefix 以换行连接后的 SHA-256。不同存储位置的同名 id 可以有不同内容，必须隔离；channel、CDN 地址和凭证不属于不可变 release 的身份。缓存不写 subscriber 的 releases/、current.json，不改变实例的已应用状态。每个文件以临时文件加原子替换落盘；整对不是事务，部分写入或混合内容由下次验签拒绝。缓存路径仍经过 Layout/PathGuard，链接或别名不会被跟随读取或写入。

缓存没有 TTL，可手工删除；cache-max-age-days 仍只属于 blob 存在性缓存。保存失败只警告，不能把已经提交的远端发布变成失败。签名或 channel 上传失败不保存本次副本。完整参数和无指针发布同样保存，但不增加它们的公钥或旧清单依赖。预览仍只读：远端回退不填充缓存，取消和准备失败不新增或修复它；旧版本或其他机器发布的版本可能继续回源。promote 与 update 不接入这份缓存。

### 记录归属与部分取代

本记录部分取代[交互发布基线预览](2026-11-01-publish-baseline-preview.md)的每次远端清单读取及不维护本地发布副本的选择，保留其 channel 权威读取、可信签名、完整载荷与只读确认边界。[发布者工作区](../architecture/2026-10-13-publisher-workspace.md)的无本地 id 记录改为可丢弃缓存，但缓存不用于校验 id 是否已使用；不可重用仍由源站判断。这两个记录仍有独立依据，保留活跃。[发布签名](2026-10-25-ed25519-release-signatures.md)、[对象存储布局](../architecture/2026-10-13-object-storage-layout.md)和[blob 存在性缓存](../architecture/2026-10-20-cheap-blob-existence-checks.md)继续持有认证、不可变对象和上传去重规则，未被取代；无记录符合归档或删除条件。

## 曾考虑的替代方案

**直接采用本地最新 id，省掉所有存储请求。** 不采用：channel 之间独立且可以由其他工作区或 promote 改动。本地副本只节省不可变清单的下载，不能决定可变 channel 的当前指向，也不提供离线发布预览。

**复用订阅者 releases/ 下的 JSON 或重新序列化后验签。** 不采用：该文件服务实例状态，未保存远端签名原字节；混用还可能破坏下一次更新。独立保存上传字节及签名可复用现有验签边界，不把本地旧状态升级成发布授权。

**读取失败仍信任缓存、忽略身份或当前公钥。** 不采用：签名副本不是额外信任根；损坏、串号和换钥不能绕过当前授权。仅本地失败可回源，源站验证失败仍关闭。

**在每次预览下载后立即缓存。** 不采用：会让取消也持久化写入，并引入准备失败时缓存修复的副作用。优先覆盖同一工作区连续发布场景，保留确认前只读保证。

## 后果

- 本地命中减少两次 GET，不减少 channel 查询、扫描、解包或分块。基线来自同一份已签署 release，不是补丁链；实际发布内容仍完全来自本次输入。
- 依赖不可变 release 契约，命中时不审计源站清单、签名或内容块是否还存在，也不能发现服务端违规覆写；删除缓存可强制下一次回源。未签名指针及并发新鲜度限制不变。
- 缓存随成功发布累积，由操作者按需清理；无自动迁移、跨机同步或缓存清理命令。两文件各自替换不锁并发写入者，验证失败最多导致回源。
- PublishedReleaseCacheTest 通过实际 Publish.run、prepare 和 Prepared.publish 验证原字节持久化、本地命中的请求节省、位置隔离、无效副本回源、当前信任根、指针权威、失败无缓存及安全写入失败不改变发布；LayoutTest 验证路径归属和非法名称拒绝。原 PublishPreviewTest 与 CLI 测试继续约束预览只读、取消和确认后的重检。
